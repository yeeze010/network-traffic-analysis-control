# 测试计划

## 1. 测试目标

验证网络流量分析监测管控软件在需求范围内的功能完整性、权限正确性、数据可追溯性和部署可操作性。

## 2. 测试分层

| 类型 | 范围 |
| --- | --- |
| 文档校验 | 必备文档、模板、工作流完整性 |
| 单元测试 | 规则匹配、统计聚合、权限判断 |
| 接口测试 | 登录、节点、会话、告警、策略、报表 |
| 集成测试 | 采集节点上报到告警生成全链路 |
| 权限测试 | 不同角色菜单、接口和数据范围 |
| 性能测试 | 会话查询、排行分析、报表导出 |
| 安全测试 | 越权访问、弱口令、审计留痕 |

## 3. MVP 冒烟清单

1. 用户登录成功并获取个人权限。
2. 新增采集节点并查询详情。
3. 查询某时间段流量会话。
4. 告警列表展示并完成一次处置。
5. 导出日报并在归档列表中可见。

## 4. 退出准则

- P0/P1 缺陷清零
- 核心接口全部通过
- 权限用例全部通过
- 部署脚本和配置说明可复现
- 验收清单中的主流程均有验证记录

## 5. 当前可执行本地验证

- 执行 `scripts/validate-docs.ps1`
- 检查 `.github/workflows/docs-governance.yml` 是否与本地校验脚本一致
- 人工核对文档目录与 README 链接
